Critical Gotchas (from investigation):
1. Use frappe.cache().delete_value() NOT delete_key()
2. Token format: lowercase 'token api_key:api_secret' NOT Bearer/Token
3. authenticate_for_2factor() sets tmp_id in frappe.local.response, needs custom wrapper
4. confirm_otp_token() takes login_manager object, NOT session string
5. get_2fa_method() does NOT exist — use frappe.twofactor.get_verification_method()
6. credentials:'include' REQUIRED on ALL fetch() calls
7. Check existing api_key before generating new — reuse to prevent orphans
8. Frappe returns 403 (not 401) for session expiry
9. vite.config.ts uses fast-glob — do NOT manually add page entries

Session 7 (Builder - subtask-6-3):
- End-to-end integration verification of all auth flows
- CRITICAL INTEGRATION BUGS FOUND AND FIXED:

  BUG 1: LoginPage.ts — API response type mismatch (CRITICAL)
    Issue: Frontend LoginResponse expected flat api_key/api_secret/expires_in
           but backend nests them under token: {api_key, api_secret, token_type}
    Impact: Login would silently fail — no redirect, no error, no token storage
    Fix: Updated LoginResponse interface to use nested token object,
         updated handleLoginSuccess to extract from result.token

  BUG 2: VerifyPage.ts — Same token nesting mismatch (CRITICAL)
    Issue: VerifyEmailResponse expected flat api_key/api_secret
    Impact: Email verification would fail to store tokens
    Fix: Updated response type, added token extraction from result.token

  BUG 3: Verify2FAResponse — Same issue for 2FA flow (CRITICAL)
    Issue: 2FA response expected flat tokens
    Impact: 2FA verification would fail to store tokens
    Fix: Updated type and extraction

  BUG 4: api.ts — FrappeError title not preserved (MEDIUM)
    Issue: Frappe _server_messages contain title field (e.g. "email_not_verified")
           but handleError only extracted message text, losing the title
    Impact: Login with unverified email would show error toast instead of
           redirecting to verify page (email_not_verified detection failed)
    Fix: Added FrappeError class that preserves title, updated handleError
         to extract title from _server_messages

  BUG 5: Dashboard redirect paths — all wrong (MEDIUM)
    Issue: LoginPage, VerifyPage, WelcomePage, and backend used non-existent paths:
           - pages/supplier-dashboard.html (doesn't exist)
           - pages/buyer-dashboard.html (doesn't exist)
           - pages/seller/seller-dashboard.html (doesn't exist)
    Fix: Updated all to use actual paths:
           - Buyer: pages/dashboard/buyer-dashboard.html
           - Supplier: pages/seller/sell.html

  BUG 6: Backend-to-frontend user field name mismatch (MEDIUM)
    Issue: Backend returns is_email_verified (number), frontend AuthUser expects
           is_verified (boolean). Backend doesn't send roles array.
    Impact: Stored user profile would have wrong field names, causing
           middleware checks to behave incorrectly
    Fix: Added BackendUser interface and mapBackendUser() mapping function
         to auth.ts. Updated LoginPage and VerifyPage to use mapping.

  BUG 7: Token refresh could corrupt tokens (LOW)
    Issue: middleware.ts refreshAuthToken expected api_key/api_secret in response
           but refresh_token endpoint (Keycloak) only returns expires_in.
           Would store undefined values, corrupting localStorage tokens.
    Fix: Added null checks — only update tokens if response has valid data,
         otherwise extend existing token expiry.

  BUG 8: Logout doesn't invalidate server session (MEDIUM)
    Issue: TopBar.ts logout handler only called clearAuth() (localStorage),
           never called backend tr_tradehub.api.v1.auth.logout endpoint.
    Impact: Server-side session remained active after client-side logout
    Fix: Added fire-and-forget apiPost to backend logout endpoint before
         clearing local auth. Error is silently caught.
